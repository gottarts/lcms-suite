# Resoconto Bugfix — autoMap e link "vedi preparazioni"
**Data:** 2026-03-11
**Branch:** master
**DB user_version:** invariato

---

## Obiettivo

Correggere due bug segnalati nel modulo Composti:

1. La funzione `autoMap` mappava la colonna CSV "Forma Commerciale" sul campo DB sbagliato (`forma` invece di `forma_commerciale`), corrompendo silenziosamente i dati importati.
2. Il link "→ vedi preparazioni" nello storico compariva anche per composti non Neat, portando a un tab inesistente e lasciando il pannello laterale vuoto.

---

## BUG 1 — autoMap: falso match su `forma_commerciale`

### File modificato
`src/renderer/pages/composti/ImportDialog.tsx`

### Causa

La funzione `autoMap` usa due passaggi di matching:

1. **Match esatto** — confronto diretto tra header normalizzato e alias
2. **Match substring** (fallback) — controlla se l'alias è contenuto nell'header o viceversa, con soglia `normalize(s).length >= 5`

La stringa `"forma"` ha esattamente 5 caratteri, quindi rientrava nel fallback substring. Poiché `"formacommerciale".includes("forma")` è `true`, il loop si fermava su `forma` prima ancora di valutare `forma_commerciale`. Il match esatto al passo 1 non aiutava perché `"formacommerciale" !== "forma"` — ma il problema era che al passo 2 la soglia `>= 5` includeva `"forma"` nel fallback.

### Fix

Modifica di una sola riga — soglia cambiata da `>= 5` a `> 5`:

```typescript
// PRIMA
if (synonyms.some(s => normalize(s).length >= 5 && (hn.includes(normalize(s)) || normalize(s).includes(hn)))) {

// DOPO
if (synonyms.some(s => normalize(s).length > 5 && (hn.includes(normalize(s)) || normalize(s).includes(hn)))) {
```

`"forma"` (5 caratteri) viene ora escluso dal fallback substring. Il match esatto al passo 1 trova correttamente `"formacommerciale"` nell'alias di `forma_commerciale`.

### Impatto

Gli alias brevi (≤ 5 caratteri) come `"forma"`, `"conc"`, `"unit"`, `"pos"`, `"mw"`, `"pm"` non partecipano più al fallback substring — solo al match esatto. Questo è il comportamento corretto: alias corti sono ad alto rischio di falsi positivi nel matching per contenimento.

## BUG 2 — Link "vedi preparazioni" visibile per composti non Neat

### File modificato
`src/renderer/pages/composti/CompostoPanel.tsx`

### Causa

Nel tab Storico, la timeline unificata include eventi di tipo `prep` costruiti da `composto.preparazioni`. Il blocco JSX che renderizza ogni evento preparazione conteneva un link `→ vedi preparazioni` che al click chiamava `setActiveTab('preparazioni')`. Il tab "Preparazioni" però è condizionato a `composto.forma === 'Neat'` (sia il `TabsTrigger` che il `TabsContent`). Per composti non Neat, cliccare il link impostava `activeTab` a un valore senza `TabsContent` corrispondente, lasciando il pannello vuoto.

In pratica i composti non Neat non hanno preparazioni, quindi `composto.preparazioni` è vuoto e il bug non si manifesta in condizioni normali. Il fix è comunque corretto per robustezza.

### Fix

Il link è stato avvolto con la stessa condizione già usata altrove nel file per il tab Preparazioni:

```tsx
// PRIMA
<button
  className="text-[11px] text-blue-600 hover:underline mt-1 block"
  onClick={() => setActiveTab('preparazioni')}
>
  → vedi preparazioni
</button>

// DOPO
{composto.forma === 'Neat' && (
  <button
    className="text-[11px] text-blue-600 hover:underline mt-1 block"
    onClick={() => setActiveTab('preparazioni')}
  >
    → vedi preparazioni
  </button>
)}
```
